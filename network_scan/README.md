# Network Map Scanner (experimental)

This is **separate from scanner.py**. It only captures game traffic generated by ordinary BlueStacks navigation and decodes observed WorldMapViewS2C responses. It does not send or replay game-server requests, inspect game process memory or modify the game.

**Status:** The offline decoder recovered 1,734 distinct bases from five test captures. The interactive capture runner and ADB-assisted jumping have not yet been live-tested on your BlueStacks UI. Do not treat a fully checked route as proof of full-server coverage.

## What is the best jump spacing?

The 1,734 bases came from many overlapping views; the largest individual response had 723 bases. Another response at X:468 Y:438 contained 695 bases with observed base positions spanning X:379–559 and Y:322–575 (~180 × 253 units).

These are the bounds of **returned players**, not proven map visibility boundaries. Zoom affects response size. Start with a fixed zoom level that still shows player bases and a 3×3 pilot, then refine spacing. The default 110 X × 140 Y spacing and assumed 0–999 coordinate range generate 63 route targets; these are unverified planning assumptions, not coverage guarantees.

## Requirements

- Python 3.10+, Windows/PowerShell, Z-Route running in BlueStacks, Wireshark/Npcap installed.
- Find your network interface: run the Wireshark dumpcap executable with the -D flag.
- ADB path and serial in config.json are used only for optional calibrated UI navigation.
- Keep packet captures private. They may contain session or account information.

## Offline analysis

From the repository root, after copying your saved PCAPNG files locally:

    python network_scan/scan.py analyze .\zroute_map_test3.pcapng .\zroute_map_test5pcapng.pcapng --out .\network_scans\baseline

Outputs: baseline/players.csv (deduplicated by server and stable player ID) and baseline/views.csv (map center, observed base coordinate ranges, record count, response size).

## Generate the 3×3 pilot

    python network_scan/scan.py plan --pilot 522 415 --step-x 110 --step-y 140 --out .\network_scans\pilot.csv

Nine destinations: X=412,522,632 and Y=275,415,555, in serpentine order. Keep the same zoom level throughout. Measure base overlap between neighboring positions and the number of new IDs at each jump.

For the initial full grid:

    python network_scan/scan.py plan --step-x 110 --step-y 140 --out .\network_scans\full.csv

For a more conservative first pass try step-x 80, step-y 100. Larger spacings might work, but must be calibrated before using them to certify coverage.

## Guided capture

    & "C:\Program Files\Wireshark\dumpcap.exe" -D
    python network_scan/scan.py run --plan .\network_scans\pilot.csv --interface 1 --dumpcap "C:\Program Files\Wireshark\dumpcap.exe" --seconds 18

Change interface 1 to the number of your active Wi-Fi or Ethernet adapter. For each destination, the program starts the local capture **before** you navigate using the game's UI. Press Enter when the destination loads. It checks for decoded map responses centered near the expected coordinates (8-unit tolerance), then checkpoints the route CSV. Missing responses are marked REVIEW, not COMPLETE. A second run skips completed targets.

Analyze the saved captures in Windows PowerShell:

    $pcaps = @(Get-ChildItem .\network_scans\pilot_captures\*.pcapng | ForEach-Object FullName)
    python network_scan/scan.py analyze $pcaps --out .\network_scans\pilot_analysis

## Optional ADB UI navigation (only after calibration)

The runner also supports mode adb, but first establish the exact screen taps for opening the coordinate navigation popup, editing both fields and confirming the jump. The following action example contains NONFUNCTIONAL placeholders, and must not be executed unchanged:

    {"actions":[
      {"op":"tap","x":100,"y":100},
      {"op":"sleep","seconds":0.4},
      {"op":"field","x":200,"y":200,"value":"x"},
      {"op":"field","x":200,"y":260,"value":"y"},
      {"op":"tap","x":300,"y":300}
    ]}

After visually verifying each action on the correct BlueStacks resolution, store the real JSON under network_scans/jump_ui.json (ignored by Git) and test one target manually. Then:

    python network_scan/scan.py run --plan .\network_scans\pilot.csv --interface 1 --dumpcap "C:\Program Files\Wireshark\dumpcap.exe" --mode adb --jump-ui .\network_scans\jump_ui.json

The program does not blindly retry ambiguous UI commands after an ADB failure. Failed or missing responses are not counted as scanned.

Future work: calibrated zoom/coverage, safer verified ADB jumps, dynamic gap-filling, map coverage visualizations, and reviewed integration into the existing history publisher. Automatic public publication is disabled.
